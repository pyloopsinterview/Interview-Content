## Question 2:  
**Which migration tools did you use and what was the purpose of using those tools?**

### Answer:
Sure.

In my **recent project with Dignity Health**, we worked on **migrating legacy Dynamics systems and related applications into the Dynamics 365 cloud environment**. For migration, we used different tools depending on the **type of data and the complexity of the migration**.

First, we used the **Dynamics 365 Data Migration Tool** mainly for **initial data migration**. This tool is helpful for migrating **standard entities like accounts, contacts, users, and CRM data** from the legacy system into the **Dynamics 365 environment**. The purpose of this tool is to **map source data to Dynamics entities and maintain the data structure during migration**.

Second, we used the **Configuration Migration Tool** for **moving configuration data**, such as **security roles, workflows, business rules, and other system configurations**. This ensures that **environment setups remain consistent across development, QA, and production environments**.

For **large datasets and complex integrations**, we used **Azure Data Factory pipelines**. The purpose of Azure Data Factory is to **handle large volumes of data, perform data transformation if needed, and automate the movement of data from source systems into Azure SQL and then into Dynamics 365**.

We also used the **solution export and import process in Dynamics 365** to migrate **custom components such as plugins, custom entities, workflows, and integrations** between environments.

Overall, the main tools we used were **Dynamics 365 Data Migration Tool, Configuration Migration Tool, Azure Data Factory, and managed solution deployment**, depending on whether we were migrating **data, configurations, or customizations**.
