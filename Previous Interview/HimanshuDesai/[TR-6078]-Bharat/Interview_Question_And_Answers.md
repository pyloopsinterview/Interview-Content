# Tricky Software Defect

## Question
Can you describe a tricky software defect that testing did not catch?

## Answer
One issue involved Kafka consumer processing logic where offset commits were happening before downstream database processing fully completed.

Under high-load production scenarios, a race condition caused duplicate processing.

The issue was not detected in testing because mocked environments did not simulate:
- Kafka rebalance timing
- Partial transaction failures
- Concurrent processing edge cases

The fix involved:
- Moving offset commits after successful persistence
- Adding idempotency validation
- Improving transactional handling
- Adding concurrency simulation tests

### Key Defect Areas
- Race conditions
- Offset commit timing
- Retry sequencing
- Production-only concurrency failures
